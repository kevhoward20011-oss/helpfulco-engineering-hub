Architecture

Authority before action.

The design treats the AI as a proposer, not the authority. Permission to act is carried through a controlled path and bound to the exact governed action.

Constitution Engine→Authority & Evidence Decision→Human Authority when required→Hard Execution Boundary→Evidence & Recovery→Change Certification

Execution controls

  • Provider & Action Normalisation: external actions are translated into a governed form before authority is evaluated.
  • Current Operating Envelope: runtime authority is tied to the active operating constraints rather than an informal prompt.
  • Single-use permits: execution authority is bound to the intended action and relevant Constitution/policy/Operating Envelope state.
  • Hard Tool Gateway: the controlled execution path remains the authority boundary; browser or UI approval alone is not execution authority.

Agent identity

  • Agent Passport: enforceable identity/scope is checked at action admission.
  • Lifecycle persistence: passport state is persisted and restored with fail-closed integrity checks.
  • Revocation: lifecycle authority can revoke a passport without granting execution authority.
  • External-action scope: the bounded GitHub read requires github:repository:read; older active passport state must be re-provisioned or recreated to carry that scope.

08

Durable review context

The Decision Centre restart path was hardened so a consequential action waiting for human review can retain the context needed to validate the later decision rather than relying on ephemeral process state.

Why it matters: an approval after restart must still refer to the same governed action, authority and review context. A stale or unverifiable review context must fail closed.
● Restart/recovery evidence retained

Governed external action in Linux OCI

The external-network/container evidence gap was exercised with a bounded GitHub repository read through the governed path inside a Linux OCI container.

Boundary: the action was constrained to the governed repository-read scope and evidence was re-checked against stable GitHub response fields and the recorded commit. This does not generalise Linux OCI proof to Windows-specific storage adapters.

Current limitations

What the current pilot status does not mean.

These constraints are part of the evidence, not footnotes to hide.

Constitution lifecycle gap remains open

The authoritative production Constitution activation, reconstruction and rollback path is not yet evidenced to the level required for a higher-readiness claim.

Backup / restore is not claimed complete

The current accepted pilot posture does not claim a completed production backup-and-restore capability.

External dependency remains bounded but real

The GitHub demonstration depends on external API/network availability. The bounded Gate 9 path did not use credentials.

Gate 9 did not exercise every subsystem

Gate 9 proves its scoped external-action path; it does not by itself re-prove every Governor component or the complete Constitution lifecycle.

Verifier independence has limits

The verifier is a separately-run process using trusted local key custody. It is not third-party verification, externally anchored verification or independent-key-custody verification.

Cross-platform evidence is specific

Local Windows storage adapters still require a Windows execution host. Linux OCI evidence should not be presented as proof that Windows-specific adapters run in Linux.

Readiness boundary

Higher-readiness claims remain locked until the evidence closes the gap.

The automated suite is strong, but test volume is not a substitute for the missing Constitution lifecycle proof.

Required proof before a higher claim

  • Authoritative Constitution activation path.
  • Constitution reconstruction after restart/recovery.
  • Rollback evidence that preserves the authority boundary.
  • Gate 10 integrated operational-governance proof.

Still separate from pilot evidence

  • Production backup and restore.
  • External evidence/audit anchoring.
  • Production observability and operational hardening.
  • Independent re-audit and stronger independent key custody.
Claims deliberately not made: current whole-product TRL 6, production-ready, independently certified, third-party verified, externally anchored, or proven safe for unrestricted autonomous execution.
