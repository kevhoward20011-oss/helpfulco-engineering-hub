Verified repair evidence

Only cases with a reproduced failure, implemented repair and verification are listed here.

Identifying a cause or proposing a mitigation does not count as a completed fix. Historical benchmark work is labelled as such.

01

Next.js #85416 — request-body race

Status: verified independent repair of a historical upstream bug.

Broken: a timing-dependent request-body race could leave a downstream Server Action with incomplete JSON.

Impact: production-style requests could fail even though the same path sometimes appeared healthy.

Our verification: repaired independently and stress-verified: 15/15 final requests successful, a 7.2 MB slow-streamed request returned 200, and static checks were clean.

Public provenance: vercel/next.js issue #85416. The upstream issue had already been fixed by Next.js in PR #85418. This portfolio case claims independent reproduction, repair and verification only — not authorship of the upstream fix.

Google Gson — historical TaRBench repair

Status: verified historical benchmark repair, not an open Google Gson issue.

Broken: the reconstructed historical UnsafeAllocatorInstantiationTest#testAbstractClassInstantiation case contained assertion behaviour that was later corrected upstream as part of Gson's Error Prone cleanup.

Our verification: the focused repaired test completed with 1 test run, 0 failures, 0 errors and Maven BUILD SUCCESS on 27 September 2026.

Public provenance: the relevant upstream change is present in google/gson commit dc20b756. This case is presented only as a historical benchmark reconstruction and independently verified repair.

03

Sonar CXX #1203 — executable-line calculation

Status: verified independent repair of a historical Sonar CXX executable-lines defect.

Broken: CxxFileLinesVisitor could count AST nodes outside the intended function-body scope as executable lines, producing incorrect coverage calculations.

Our verification: the focused CxxFileLinesVisitorTest#TestExecutableLinesOfCode repair was verified under the era-appropriate Temurin Java 8 runtime: 1 test run, 0 failures, 0 errors, 0 skipped; Cxx :: Sensors SUCCESS; Maven BUILD SUCCESS on 29 September 2026.

Public provenance: SonarOpenCommunity/sonar-cxx issue #1203. The original upstream issue was completed in 2017. This portfolio case claims independent reconstruction, repair and verification only — not authorship of the upstream fix.

04

go-jsonnet #484 — Python binding post-fork deadlock

Status: verified independent repair of the reproduced deadlock behaviour; upstream issue remains open and this is not presented as an accepted upstream patch.

Broken: after the Go runtime was initialised in a parent process, a Linux fork() child could enter jsonnet_make() with inherited runtime state whose supporting threads no longer existed. The result was a deterministic 0%-CPU hang.

Repair: detect the unsafe post-fork process state before entering jsonnet_make(), then fail immediately with an actionable error instead of entering a Go runtime state that cannot safely recover.

Our verification: the unpatched Linux case hung for 300+ seconds; the repaired path fails immediately. Regression matrix 4/4; full Python suite 14/14 on Linux and macOS; C-bindings compatibility 31/31; go test ./... reported no failures; normal evaluate_snippet, evaluate_file, spawn and parent-process operation all passed. No public ABI change.

Environment lesson: macOS alone produced a false pass because the inherited Go runtime state differed. Linux verification exposed the earlier jsonnet_make() deadlock, so the final defence was moved ahead of that call.

Public provenance: google/go-jsonnet issue #484. HelpfulCo's claim is limited to independent reproduction, repair and verification of the observed deadlock behaviour in the tested environments.

Publication rule: a case is added here only when the failure, repair and verification can all be defended. Investigations and diagnoses stay off the completed-repair list until a real fix exists.
